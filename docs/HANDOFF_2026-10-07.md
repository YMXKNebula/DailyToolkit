## 2. 项目范围与维护约束

- DailyToolkit 是自行编写的 Windows 本地日常工具集合，与用户的独立游戏项目完全分开。不能修改、借用或整理另一个项目。
- 项目、仓库、程序集和产品名称使用 DailyToolkit。DailyUSE 只可能出现在旧配置兼容逻辑、历史说明或被忽略的旧编译缓存中；不能删除仍需读取的旧配置。
- 优先级为实际放大画面的渲染响应与帧率，其次画质，再优化开启放大框的速度和闲置占用。这里的“启动速度”特指放大框从关闭到显示的时间。
- 不改变已经确认的用户行为，不为抽象层次或目录美观重写项目。保留直接 GPU 路径、自定义测试执行器和具体的会话资源所有者。
- 界面文字要求正式、简短、明确。避免多余说明、营销文字和实现细节进入普通操作界面。
- 明确不泄露个人信息。设备报告、截图、天气原始缓存、本机路径、账户标识、设置和凭据不上传公开仓库，也不放入便携包。
- `artifacts/`、`.local/` 已被 Git 忽略，保存本地检查结果和开发环境。不要使用 `git add -f` 提交这些目录。
- 用户已允许上传完成的项目修改。只提交经过检查的项目内容；不上传未检查的个人文件。不要擅自终止用户正在使用的软件或修改本机启动注册。

代码许可证为 MIT。用户授权使用的荷花照片位于 `src/DailyToolkit.Desktop/Assets/lens-preview.jpg`，没有水印；素材授权与代码许可证分开，遵守仓库的素材许可说明。README 中关于带反作弊的多人竞技游戏可能导致封号、谨慎使用、后果自负的说明需要保留。

## 3. 0.6.1 的完成内容

### 3.1 侧栏选项与配置区的波浪

此前整个配置区展开得过早，用户难以看到颜色从选项开始传播。本版改为两阶段：

1. 从被点击选项的**最左侧**向右扫过整行，约占总时长的 30%。这一阶段右侧配置区仍显示完整的原页面。
2. 从侧栏连接处继续向右展开进入配置区，约占总时长的 70%；边缘带有主题强调色的柔和渐变。

默认总时长 **140 毫秒**。设置目录与收藏目录使用同一效果。选中行和右侧配置区使用相同的选中背景色，连接处有圆润过渡。

动画保存实际显示的旧画面，点击或快速中断时从当前画面继续；不会在起始一瞬间透出目标页面。标题栏和窗口控制栏不参与动画。完成、取消或卸载后释放快照与动画资源。

主要实现：`Controls/TideTransition.cs`、`MainWindow.Navigation.cs`、`Controls/NavigationConnector.cs`。

### 3.2 功能启用按钮

除设置目录外，工具入口旁的总开关：绿色代表可用，红色代表停用。停用停止该功能并注销快捷键，仍可打开工具页查看；重新启用仅恢复可用性，**不自动开启放大框**。收藏列表中的同一工具共享状态。

红绿变化从按钮正中心向四周扩散，同时渐变，默认 **100 毫秒**。两种颜色共用固定单位坐标与同一圆角轮廓，避免色块错位。快速反向切换保留当前已经显示的复合颜色；动画结束和控件卸载时释放资源。

主要实现：`Controls/FeatureSwitch.cs`、`Presentation/GamingViewModel.cs`。

### 3.3 软件运行与动画速度

设置左侧目录为 **主题配色、软件运行、电脑详情、关于**。“启动”和“后台运行”合并到“软件运行”，保留原授权、保存、失败回滚和托盘行为。

主题配色中的“切换动画”增加统一速度设置：**0.1–2 倍，步长 0.1，默认 1 倍**。侧栏波浪、星形/齿轮切换和工具总开关共用速度。1 倍对应本版的 140 毫秒波浪、100 毫秒按钮及原有 460 毫秒星形/齿轮切换。时长按速度缩放。

旧设置默认 1 倍；超界值限制到范围内，数值取整到 0.1，非有限数值恢复为 1。关闭软件动画、Windows 关闭客户端动画或系统启用高对比度时直接切换。不要为让动画测试运行而修改用户的系统动画设置。

旧页面路由保持兼容：`settings-startup`、`settings-background` 映射到 `settings-runtime`；`settings-animation` 映射到主题配色。

## 4. 已确认的界面、配色与运行行为

### 4.1 导航与收藏

侧栏直接列出工具，取消早期游戏/日常等分类和下拉详情，工具页显示完整设置。工具顺序可调整并持久化；未知工具的顺序与收藏 ID 保留，以便以后接入。

侧栏底部的星形和齿轮大小相同，在两个等宽区域居中，彼此留出间隔。点击星形打开或关闭收藏，点击齿轮打开或关闭设置。收藏和设置互斥，共享进入前的常规页面作为返回位置；从收藏转到设置后关闭，应返回主界面，不能退回收藏。

星形与齿轮的进入动画展开、退出动画收回。填色作用于放大的动画形状；工具栏原图标保留既定设计。动画覆盖标题栏以下的软件内容；不覆盖标题和最小化、最大化、关闭按钮。快速切换保持画面连续。

产品名称、版本、作者、许可和项目主页位于“关于”。窗口与主要控件使用圆角；窗口仍使用 Windows 原生窗口能力。

### 4.2 主题编辑

预设为浅色、深色、薄荷、海蓝、薰衣草、暖沙、玫瑰、石墨、纯白、深海、暮紫、琥珀。预设按钮只显示名称，选择后立即应用到全局，并同步详细配置。

“颜色详细配置”在配色预览旁；窄窗口改为上下排列。详细编辑只修改预览草稿，点击“保存配色”后影响全局。取消或恢复预览默认配色不能误写未保存草稿。保存操作按钮放在预览下方，详细色号列表单独滚动。

可设置背景、文字、边框、强调色、选中背景、提示、收藏按钮/动画、设置按钮/动画、滚动条和滑块的颜色。主题需要同时适配收藏及设置按钮。滚动条与调节滑块的轨道和滑块颜色都要跟随预设并支持自定义。自选颜色入口统一为彩色轮盘。

### 4.3 本地数据与闲置

电脑详情首次进入时才启动本机检测。时钟、网络和天气等周期刷新只在该页位于前台时运行。日期来自本机时钟，网络状态来自 Windows，天气读取 Windows 已有的小组件缓存或任务栏文字；软件不自行调用在线天气接口或主动探测联网状态。

窗口失去活动、隐藏或最小化时暂停照片预览；闲置两秒后异步释放预览 GPU 资源，保留最后一张预览，恢复时可立即显示缓存。必须保留代次检查，防止延迟释放影响新建资源。

主窗口隐藏和预览闲置不能降低实际放大框的捕获频率、画质或全局快捷键响应。不要给实际捕获路径增加界面定时器、逐帧 Dispatcher、CPU 读回或诊断日志。

### 4.4 自启动、管理员与后台

后台运行可分别设置关闭窗口、最小化时留在托盘；显式退出才停止工具、注销快捷键并释放托盘。软件与托盘使用同一 DT 组合字标。单实例按当前用户划分，重复打开恢复正在运行的窗口。

启动选项默认关闭，修改后自动保存，没有“应用启动设置”按钮。管理员启动与静默启动在开机自启下方，可兼容启用。

普通自启使用当前用户启动项；管理员自启通过当前用户已授权的最高权限任务运行**整个软件**。首次启用或关闭后再次启用时请求一次 UAC，后续自启不重复请求。已提升的进程直接更新自己的启动注册，不重复授权或重启。

静默选项变化只保存本地偏好，不重新注册或请求授权。自启与管理员选项变化才更新 Windows 注册。同一批修改合并，等待授权时的后续修改串行处理；授权取消或保存失败时恢复对应启动选项，不丢失同期其他外观修改。

任务身份核对使用 SID，并兼容 Windows 返回账户名；同时检查任务说明和执行动作，拒绝修改不属于本软件的同名任务。不保存密码。移动程序前应关闭自启，再在新位置启用；任务被外部删除后需要重新启用。

本轮构建和界面测试没有替用户启用、关闭或改写真实启动注册。

## 5. 屏幕局部放大：必须保留的交互规则

### 5.1 基本操作

- 快捷键可自选或留空，默认 `Ctrl + Shift + F8`；在后台也有效。同一个键负责开启和关闭，提供切换与按住模式；按住模式松键隐藏。
- 固定是默认位置模式。切换到固定保持实际当前位置和采样偏移，**不回中**。
- 恢复默认按钮位于设置最下面；恢复默认会停止并回中，同时保留快捷键、触发模式、收藏与工具启用状态。
- 可移动模式在放大浮窗的画面任意位置按住左键拖动整个框。点击由浮窗接收，下方窗口不响应；固定模式继续鼠标穿透。
- 保留拖动辅助线与屏幕中心吸附，删除单独的回中按钮。中心吸附是严格位移规则的明确例外；原始累计位移保留以便脱离吸附。
- 照片预览的可移动位置与实际放大框位置独立，不能互相移动。
- 放大倍率 1–10 倍，倍率设置下方有滚轮调节开关；缩放不能让框消失。不提供屏幕选择、锐化调节或整个屏幕复选框。
- 自动使用开启时鼠标所在屏幕；请求 Windows 无边框捕获以移除屏幕四周黄色线条，只保留用户设置的渲染框边线。能否获得无边框许可由 Windows 决定。

### 5.2 位移、边缘与跨屏

逐轴处理采样与输出耦合。同屏可移动时根据实际鼠标位移移动；输出触边时该轴允许采样继续移动，反向拖动时重新在输出中心耦合，并处理剩余位移。X/Y 轴独立，不以一个轴的边缘状态影响另一轴。

跨屏虚拟框与当前输出框关于相邻屏幕共有边缘或屏幕间隙中点**对称**，并将目标框限制在目标屏内。虚拟框只用于交接判断，不另开可交互浮窗。真正切换发生在鼠标越过目标虚拟框中心的相关轴时，不能进入目标屏或碰到边缘就直接切换。

跨屏后，穿越轴恢复耦合；另一轴按鼠标所在位置处理边缘采样，当鼠标落在框中心的相反半侧时限制到框中心，保持用户要求的耦合。保留中心吸附例外。不同屏幕比例、尺寸及浮点中心线需要按实际物理像素坐标处理，不能通过重置鼠标位置掩盖几何错误。

切换捕获来源与资源更新不得阻塞鼠标钩子。输入回调立即将位移累加到纯几何状态，合并最新状态，再由 Dispatcher 的 Input 优先级应用原生窗口及必要资源调整。停止会话作废旧输入；仅切换捕获来源不能清掉拖动队列或残留“已排队”标记。

### 5.3 框体预设与资源复用

尺寸预设为小 20%、中 30%、大 40% 以及自定义。比例支持跟随屏幕、1:1、16:9、4:3、21:9；固定比例按屏幕百分比的外接矩形限制计算，不把宽高都独立拉伸成相同百分比。

跨屏交接根据目标屏幕数据重新计算预设输出尺寸，同时维护对称交接规则。自定义宽高独立保存，不因选择预设而丢失。

同一个原生浮窗和指针控制器跨屏复用；仅输出尺寸变化才替换渲染器，仅真正交接时切换捕获来源。窗口坐标和尺寸不变时跳过相同的原生调用；辅助线仅在状态变化时更新。

### 5.4 捕获、画质与性能

实时路径保持 `Windows Graphics Capture → LensCapture → LensGpuRenderer → Lens.hlsl → LensNativeWindow`。`ScreenLensSession` 管理所有权与生命周期；实时图像帧不能经过 ViewModel、事件转发、CPU 图像副本或 UI 绑定。

首帧及失败才返回界面线程；保留开启超时与代次检查，防止关闭后旧回调重新显示浮窗。倍率和位置只更新必要参数，不能每次重建整个会话。0.6.1 没有修改捕获、着色器、拖动或 pacing 代码。

“跟随源帧率”需要受实际源帧交付驱动，不可用 UI 刷新定时器代替。Windows 捕获、显示器刷新、驱动、HDR 或独占全屏会影响最终效果；现有测试不能保证任意游戏的帧率完全一致，也不能声称放大能够生成源画面中不存在的细节。

在仓库根目录的 PowerShell 中运行：

```powershell
./scripts/build.ps1
```

需要 .NET 10 SDK；脚本在 `.local/` 中放置 CLI 与 NuGet 缓存、使用 Release 构建并执行两个自定义测试程序。不要用一次 `dotnet test` 无用例的成功输出替代现有检查。

仅在新的界面修改或未解决问题需要时补充界面导出：

```powershell
$desktopChecks = './tests/DailyToolkit.Desktop.Tests/bin/Release/net10.0-windows10.0.26100.0/DailyToolkit.Desktop.Tests.exe'
& $desktopChecks --interface-checks './artifacts/interface-handoff'
```

真实捕获几何检查需交互式 Windows 桌面与可用的 Direct3D/捕获权限：

```powershell
& $desktopChecks --live-lens-only
```

人工输入诊断可能暂时改变鼠标或展示测试浮窗，不能在用户操作其他窗口时无提示地反复执行。几何合成测试使用 `ScreenLensSession` 的 `nativePointer: false`，隔离物理指针与窗口鼠标消息；产品默认保持 `true`。该隔离只改变输入来源，仍测试真实原生窗口、GPU 与捕获。

跨屏回程的测试必须继续保持原拖动握持关系：按当前输出中心计算鼠标**增量**，不能直接令绝对鼠标坐标等于输出中心。虚拟中心的半像素阈值按方向向下/向上取整。

主要检查入口：

- Core：`tests/DailyToolkit.Tests/LensFrameSizeTests.cs`、`LensMovementTests.cs`、`LensLayoutTests.cs` 等，涵盖几何、比例、方向、奇数分辨率、旧设置及环境/协议。
- Desktop：`ToolkitInterfaceTests.cs`、`TransitionContinuityTests.cs`、`SettingsCompatibilityTests.cs`、`StartupTests.cs`、`LensPresetRelayTests.cs`、`PreviewTests.cs` 等，涵盖实际控件、设置和原生资源。
- 历史记录：`docs/RELEASE_060_CHECKS.md`、`RELEASE_057_CHECKS.md` 等，只用于对应版本的证据；`TARGETED_REFACTOR.md` 保留历史演进，里面的锐化、分类或测试计数不代表现行界面。
