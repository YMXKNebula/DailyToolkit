# 框架说明

DailyToolkit 的界面和工具都在本机运行。第一版先做 Windows，桌面程序用 WPF，公共代码放在独立的 C# 项目里。

## 目录

| 目录 | 用途 |
| --- | --- |
| `src/DailyToolkit.Core/Environment` | 信息格式、适配规则、Windows 天气缓存解析和网卡流量采样 |
| `src/DailyToolkit.Core/Tools` | 工具登记、运行条件检查、本地进程调用 |
| `src/DailyToolkit.Desktop/Environment` | Windows 信息读取 |
| `src/DailyToolkit.Desktop/Presentation` | 页面状态和操作 |
| `src/DailyToolkit.Desktop/Gaming` | 放大运行会话、原生窗口、捕获与显卡渲染 |
| `tests` | 适配、进程通信及界面生命周期检查 |
| `scripts` | 编译和打包 |

## 启动和检测

先创建窗口，随后在后台读取基础信息。处理器、内存、电源和系统版本使用 Windows API 或只读注册表查询。详细检测完成后更新页面，不等待检测才显示窗口。

处理器核心数和显卡驱动通过系统自带的 Windows PowerShell 查询 CIM，整个查询限时 10 秒。软件列表只读卸载记录，不使用会触发安装程序检查的 `Win32_Product`。Python、Node.js、.NET SDK 的版本检查每项限时 3 秒；跳过可能打开商店的执行别名。

读不到某项时保留基础信息，并显示不可用。关闭窗口会取消检测并终止尚未完成的检测进程。普通启动不写报告，用户点击“保存报告”时才写入所选位置。

报告不采集序列号、账号、网络地址或访问令牌。运行程序的完整路径供内部调用使用，不导出。软件名称和发布者仍可能包含个人或组织信息，分享报告前需要自己查看。

## 电脑页数据来源

“电脑”页显示日常状态和配置。完整配置、运行环境、软件列表默认折叠。界面使用像素对齐和 Display 文字排版；预览按窗口的实际 DPI 输出。

- 日期和时间读取 Windows 本机时钟，每秒更新。软件不自行校时。
- 网络状态来自 Windows Network List Manager。它反映 Windows 当前的判断，不保证每个网站都能访问；DailyToolkit 不发送 Ping、DNS 查询或 HTTP 连通性请求。
- 流量读取有默认网关的活动网卡计数器，每三秒采样。它包含本机这些网卡的流量，不是互联网测速；使用多个物理或虚拟连接时可能包含多个连接的统计。不记录网卡名称、IP、MAC 或 Wi-Fi 名称。
- 天气优先读取 Windows 小组件在本机保存的天气缓存，每分钟最多尝试一次；手动刷新可以立即重读。页面显示温度、天气描述、可用的地点和观测更新时间，保持缓存中的摄氏或华氏单位。超过三小时标为“缓存较旧”，超过一天不再作为可用天气显示。没有可用缓存时，尝试通过 UI Automation 读取任务栏现有的天气文字，不打开或点击系统小组件。

缓存来源为 `%LOCALAPPDATA%/Packages/MicrosoftWindows.Client.WebExperience_cw5n1h2txyewy/LocalState/DiagOutputDir/IDX_CONTENT_TASKBARHEADLINES.json`，目前在本机的 Windows 11 小组件缓存上验证。只解析 `WeatherSummary` 卡片中的 `WeatherOverview`，提取当前天气、单位、城市和观测时间；不解析新闻、账号、访问令牌、精确坐标或浏览器缓存。这个文件属于 Windows 内部格式，不是公开天气 API；Windows 改变格式时可能需要调整读取器。

读取器兼容 UTF-8、UTF-16 以及不带 BOM 的 UTF-16 文件，共享只读打开并限制文件为 4 MB。文件正在写入、格式变化、缓存缺失或超时时，显示具体的不可用原因。天气缓存由 Windows 自己更新，DailyToolkit 不会自行联网，也不修改小组件开关；“刷新”只重读本机已有数据。

天气读取放在独立的隐藏进程中，限时三秒；关闭主窗口会取消周期读取并清理子进程。报告额外包含当前本机时间、Windows 网络状态、采样流量和已取得的天气摘要、城市及观测时间，不保存原始缓存内容。

## 适配规则

检测任务的并发数按可用逻辑处理器的一半计算，上限 8。内存低于 8 GB 时最多 2 个，低于 4 GB 时最多 1 个。使用电池且电量不超过 20% 时最多 2 个。

界面不使用卡片阴影。窗口宽度小于 900 时缩小留白，高对比度模式使用系统颜色。`AdaptationPolicy` 保留低内存和低电量时减少界面效果的建议，后续工具可以按自己的工作量使用它，并非所有工具都要开满并发。

## 接入本地工具

新增工具应有自己的页面或 `UserControl`，工具设置与命令放在自己的 ViewModel；主窗口只接入口，不继续承载各工具的完整界面和运行资源。这里不要求新的导航框架或通用服务层。

屏幕局部放大的 `GamingViewModel` 管理绑定、命令、设置、收藏及鼠标所在屏幕的识别；`ScreenLensSession` 拥有浮窗、捕获、渲染器、鼠标监听、辅助线和启动超时，并统一启停及释放。首帧和失败才回到界面线程，实时帧仍直接从 `LensCapture` 进入 `LensGpuRenderer`，不经过会话事件、绑定或 ViewModel。倍率和同屏位置只更新参数及已有窗口。跨屏时切换捕获来源，保留浮窗及拖动；仅输出尺寸变化时更换渲染器，鼠标钩子不等待资源切换。界面不再提供屏幕选择和锐化调节。

现有放大设置仍保留在主窗口，因为快捷键编辑需要暂停全局注册，并与窗口焦点处理关联；当前拆出会增加转发。`MainViewModel`、自定义测试执行器和诊断命令也保留。测试按领域分文件，快捷键诊断按场景分方法，不增加工程依赖。

默认配置读取新目录；新目录尚无对应文件时，兼容读取旧版 `%LOCALAPPDATA%/DailyUSE/`。保存只写新目录，不修改旧文件；已有新配置优先。开发检查使用独立临时配置，避免用户关掉滚轮后影响测试。

用 `ToolDefinition` 描述工具，并通过 `ToolCatalog.Register` 登记。`ToolRequirements` 可以声明系统架构、Windows 内部版本、内存、处理器指令和运行环境版本；运行前调用 `ToolCatalog.Check`。未确认的信息不会被当作满足已声明的运行条件。

C# 工具可以直接在进程内运行。其他语言写的工具，或需要单独进程的 C# 工具，通过 `ProcessToolRunner` 调用自己的可执行程序。主程序不会自动扫描或运行网上下载的插件。

调用方提供完整的可执行程序路径和独立参数，不拼接命令行。每次调用启动一个进程，向标准输入写入一行 UTF-8 JSON，随后关闭输入。输入示例：

```json
{"Operation":"example","Input":{"text":"本地内容"},"ProtocolVersion":1}
```

工具把结果写到标准输出，日志写到标准错误。正常完成返回退出码 0 和一个 JSON 对象：

```json
{"Success":true,"Data":{"text":"处理结果"},"Error":null}
```

操作失败可以返回 `Success: false` 和 `Error`；主程序应把错误展示给用户。主程序限制输出大小，支持超时和取消，并在取消或通信失败时终止子进程树。这个接口不是安全沙箱，工具仍以当前用户权限运行。

左侧直接列出“电脑”和已接入的工具，后续工具也在这里添加入口。入口由 `MainViewModel` 中的 `NavigationItem` 列表提供，排序写入 `navigation.json`，收藏模式筛选同一批入口，不另外创建工具实例。未知工具 ID 在保存顺序和收藏时保留，方便后续接入。

侧栏底部的星形和齿轮分别在两个等宽列中居中。收藏夹和设置是互斥面板，共用进入前的常规页面作为返回位置，相互切换不增加返回层级。关闭面板后恢复主界面及原工具选择。设置使用独立导航目录，主题配色、后台运行、启动和关于每次只显示一页；切换动画并入主题配色，旧 `settings-animation` 路由映射到主题配色。切换类别后重置滚动位置，本机数据刷新不会重置滚动。产品信息集中在关于页。软件界面偏好保存在 `settings.json`，不与工具设置混用。

按钮填色和动画填色共用 `AnimationBrush`，主题预览同步显示此颜色。进入时形状旋转展开，同时由按钮颜色渐变为目标页面；退出时反向旋转收回，同时将旧页面渐变为按钮颜色。缩放、旋转和透明度共用 460 毫秒的正弦加减速，没有单独等待填色的阶段。进入时旧页快照位于形状外，退出时旧页快照位于形状内；目标页保持正常渲染，无需逐帧截图。齿轮动画中心填满，小图标中心保持留空。轮廓冻结后通过 `RenderTransform` 缩放和旋转，不在动画中改变布局。快照和遮罩只在标题栏下方，标题栏通过 `WindowChrome` 保留拖动、缩放和窗口控制。连续点击只保留最新动画，调整窗口大小或关闭动画会立即清理遮罩，动画结束后释放快照和变换。通用配色与放大框配色共用彩色轮盘控件，高对比度时使用系统颜色。

切换快照从不透明的窗口内容按当前 DPI 渲染一次，再裁出标题栏下面的部分。不能直接渲染已附着的 `BodyContent`，否则它在父容器中的位置会被带入快照，产生纵向偏移和透明空隙。快照按原始像素显示；先安装旧画面与初始遮罩，再更改页面绑定。新页面只按展开或回收遮罩逐步显现。反向点击或改点另一图标时，保存当前实际合成画面作为下一次动画的起始帧。

主题有十二套预设，按钮只显示名称，点选后立即保存并应用整套配色及同步的星形/齿轮按钮和动画颜色。各套预设使用不同的窗口、卡片和侧栏色调，并提供多种深色配色。`Theme` 与 `AnimationColor` 表示已应用值；`PreviewTheme`、`ThemeColors` 与 `PreviewAnimationColor` 保存编辑草稿。详细色号只通知预览，不更新窗口资源或写入设置。点击保存后才原子提交整套草稿，失败时保留草稿及原配色。撤销与恢复预览默认只修改草稿；选择预设替换草稿并同步所有详细配置项。窗口资源始终从已应用值读取，其他设置的保存也不会误应用草稿。详细配置默认收起，位于主题页预览下方。

`MainWindow.Runtime.cs` 管理隐藏、恢复和真正退出，`Runtime/TrayIcon.cs` 使用 Windows 通知区接口。隐藏时不停止放大或全局快捷键；显式退出时停止捕获、注销快捷键、取消本地检测并删除托盘图标。隐藏窗口和管理员窗口可以通过本程序注册的恢复消息重新显示，实例互斥按当前用户划分。

`Runtime/StartupRegistration.cs` 只管理当前用户的 DailyToolkit Run 值和 `DailyToolkit-<SID>` 任务。普通自启写入用户启动项；管理员自启用交互用户、最高权限的任务，不保存密码，不限定运行时长，允许电池供电。首次启用通过本程序的 UAC 辅助入口注册，身份必须与原用户 SID 一致。任务只向所有者授予读取、执行、删除权，普通权限不能替换管理员动作；系统和管理员保留完整权限。关闭自启删除任务，重新启用需再次授权。注册成功后通过任务重启整个软件，静默选项由新进程读取同一份本机设置。任务缺失时不会自动改走 UAC 自启动。预览和检查模式不注册真实启动项。

Windows 返回的任务账户既可能是 SID，也可能是账户名。读取、修改和启动时先将账户名解析为 SID，再确认其属于当前用户，同时保留任务说明和动作检查。不能仅按显示名称判定，也不能因为 Windows 返回了账户名就将本程序已注册的任务当作外部任务。当前进程已经提升权限时，直接注册或修改自己的启动项，不再发起 UAC 或重复重启。

启动选项改变后自动保存，同一 UI 事件中的修改合并执行，授权等待期间的后续修改串行处理。只有自启或管理员选项变化才更新 Windows 注册；静默选项变化只保存偏好，不重新授权或重启软件。首次切换管理员自启成功后才重启。取消授权或本地保存失败时还原对应启动选项，保留同期修改的其他界面偏好。初始化和目录切换不触发启动注册。

DT 图标的矢量源是 `Assets/dt.svg`，`scripts/create-icon.ps1` 生成 PNG 和包含九种尺寸的 ICO。程序窗口、便携 exe 和托盘共用这些素材。

框体颜色保存在 `GamingPreferences.BorderColor`，使用 `#RRGGBB`。旧配置缺少此字段时使用默认绿色。颜色随来源参数一次性更新，直接写入 GPU 常量；更换颜色时会刷新最近画面，照片预览使用相同参数。框内采样和实时帧路径保持原样。

公共调用接口已验证，工具页面和依赖分发在接入时补齐。Python 或 Node.js 工具可以附带自己的运行环境。

## 本地检查

`scripts/build.ps1` 运行核心检查和 WPF 界面检查，包括低配置适配、缺少运行环境、UTF-8 通信、超时、取消、输出过量、搜索、后台响应、时钟跨日、天气不可用和网卡切换计数，以及关闭时清理。

开发时可用下面的参数生成本地检测报告或隐藏窗口预览。它们不会联网，生成文件不要提交进仓库：

```powershell
DailyToolkit.exe --diagnose "D:\临时\report.json"
DailyToolkit.exe --preview "D:\临时\home.png" --width 680 --height 650
DailyToolkit.exe --preview "D:\临时\details.png" --details
DailyToolkit.exe --preview "D:\临时\software.png" --software
DailyToolkit.exe --preview "D:\临时\theme.png" --page settings-theme --theme 海蓝 --theme-details --preview-color Accent=#A24568
```

输出目录需要事先存在。预览同时生成 JSON 报告；界面计时从应用创建开始，不能代替不同电脑上的冷启动测试。打包采用独立运行的单文件应用；首次运行仍可能需要在系统临时目录解包原生组件。
