# 屏幕局部放大

在 DailyToolkit 左侧选择“游戏”里的“屏幕局部放大”。收起时只占一行，显示快捷键和模式；点击名称或右侧箭头展开倍率、宽度、高度和帧率。屏幕由鼠标位置自动识别，没有屏幕选择下拉框，也不再提供锐化调节。宽、高可以分别用滑块或输入像素值调整，宽度范围 160–1600，高度范围 120–1200，实际框不会超过当前屏幕。只放大局部框，没有“整个屏幕”复选框。

右侧荷花照片是本机效果预览，使用与实际放大框相同的画面处理。上图按当前屏幕的比例展示位置及大小，下图显示框内细节；尺寸、倍率改变时同步更新。可以拖拽照片里的放大框、滚动鼠标试效果。窄窗口会把预览放到设置下方。照片随程序保存，展开设置才读取，不启动屏幕捕获。

照片的使用范围见 [素材说明](../src/DailyToolkit.Desktop/Assets/README.md)。

详细设置里的“位置”可以选“固定”或“可移动”，选择会保存在本机。默认固定，开启时检测鼠标所在屏幕，首次在这块屏幕的中央显示。固定只锁住当前位置：把框拖到别处后切回固定，不会回中；在同一屏幕关闭后重新开启，也保留本次运行的位置。固定时鼠标点击可操作下面的窗口。

选“可移动”后，按住放大画面任意位置的鼠标左键，拖动的是整个渲染浮窗，边缘和中间都可用。鼠标越过屏幕边界时，浮窗移入对应屏幕，并切换到这块屏幕的画面，左键可一直按住，不用重新开启。框的边界限制在当前屏幕内；进入较小屏幕时临时缩小，回到较大屏幕时恢复设置的尺寸。此模式下框内左键用于拖动，摆好位置后可以切回固定再操作下面的窗口。

拖动时，桌面上会显示当前屏幕的水平、垂直中心虚线，线段避开放大浮窗，跨屏时也会切换。浮窗中心距离屏幕中心线不超过 24 个实际像素时，对应方向会吸附，辅助线变黄；继续拖出这个范围即可脱离，松开后两条线隐藏。辅助线使用桌面坐标，不画进放大内容。切换位置模式不需要关闭放大框。照片预览使用相同的吸附规则，但两边位置独立，互相拖动不会影响另一边；切回固定时各自保留位置。

详细设置最下方的“恢复默认”仍然会把放大框和照片预览回中，并关闭放大框，恢复鼠标所在屏幕、640 × 384 像素、2×、跟随画面帧率和固定模式；保留自定义或空快捷键、按住／切换模式和收藏，后台快捷键仍可重新开启。

倍率范围为 1–10×。倍率滑块下面的“滚轮调节”默认开启，鼠标放在框内时每格滚轮调整 0.25×，到达上下限仍保持显示。关闭后，实际浮窗和照片预览都不再用滚轮调倍率，上方滑块仍可使用。开关即时生效并保存在本机，“恢复默认”会重新开启它。固定模式的点击继续传给下面的窗口；可移动模式框内的左键及拖动由工具处理，框外鼠标操作不变。关闭放大框时停止捕获，并释放渲染资源和鼠标监听；本次运行中的拖拽位置和倍率会保留，重新开启时继续使用。

点亮星标后也能从“收藏夹”打开同一个工具，设置和运行状态共用。收藏列表保存在 `%LOCALAPPDATA%/DailyToolkit/favorites.json`，取消星标移出收藏夹，不会删除工具。

放大框不抢焦点，固定模式的点击可以穿过它。框外保持原来的桌面或游戏画面。游戏建议使用窗口或无边框模式；独占全屏、禁止捕获的画面和某些远程桌面环境可能无法显示。

> 屏幕局部放大用于带有反作弊的多人竞技游戏时，可能导致封号。请谨慎使用，后果自负。

## 快捷键

默认 `Ctrl + Shift + F8`，开启和关闭共用这一个快捷键。软件启动后就注册，不需要先手动开启放大框；其他软件在前台或 DailyToolkit 最小化时也能呼出，不把 DailyToolkit 主窗口拉到前台。

- **切换**：按一次开启，再按同一快捷键关闭。持续按住不会反复切换；正在等待首帧时，也能用同一个按键关闭。
- **按住**：按住组合键时开启，松开其中任意一键就关闭；在后台也会检查松键。

点击输入框，再按想用的组合键即可修改，按 Esc 退出输入。点击“清空”后显示“无”，不占用快捷键，详细设置中的按钮仍可用。

快捷键和模式保存在本机 `%LOCALAPPDATA%/DailyToolkit/gaming.json`，重启后保留。旧版自定义及空快捷键会保留，旧版单独的关闭键不再注册。编辑快捷键时暂停注册；更换按键或模式会关闭当前放大框，避免保留旧按住状态。系统或其他软件占用按键时会提示，可以另选或清空。

关闭放大框会停止捕获，并释放浮窗、显卡资源和鼠标监听，之后即可调整画面设置。后台快捷键仍然注册，下次按键会重新开启；详细设置中也只有一个“开启 / 关闭放大框”按钮。关闭 DailyToolkit 主窗口会退出软件并释放快捷键；后台使用时保持软件运行或最小化。

## 画面处理

Windows Graphics Capture 负责取得当前屏幕的画面，Direct3D 11 在独立浮窗内渲染。跨屏时更换捕获来源，保留原生浮窗和鼠标拖动；输出尺寸不变时复用渲染器。捕获切换在界面线程中处理，鼠标监听只合并最新的位置请求，不等待显卡初始化。原始屏幕由 Windows 和游戏继续显示，DailyToolkit 只处理框内的区域，不注入游戏，不修改游戏文件或画面设置。

框内使用 16 点 Catmull-Rom 插值重建像素。插值权重按两个方向各算一次，默认 35% 锐化复用同一批采样里的细节，避免重复运行多个插值核；锐化按原始像素尺度计算，10× 时仍有效，并限制在附近原始像素的颜色范围内，减少亮边和暗边。界面不再提供锐化滑块。它会改善缩放后的平滑度和锐度，但不能重新渲染外部游戏的场景，也不能恢复原图没有的真实细节；不是 AI 超分辨率。

主界面出现后，会在后台准备并缓存放大着色器的字节码，快捷键开启和后续重新开启时直接复用。此阶段不创建捕获会话或保留放大显卡资源；关闭放大框仍释放浮窗、捕获和渲染对象。

显示与采样均使用屏幕实际像素，支持负坐标的副屏和不同缩放的屏幕。框保持独立的 GPU 渲染目标，通过 Windows 的捕获排除设置避免浮窗反馈，不发送、录制或保存屏幕内容。只有用户开启工具后才启动捕获，正常启动仍先显示主界面。首次开启时通过 Windows 的 [无边框捕获接口](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired) 请求许可，允许后关闭屏幕四周的黄色提示，只保留渲染框边线；系统版本或权限不允许时仍会显示系统边框。许可在本次运行中复用。

帧率优先于清晰度，默认“跟随画面”，Windows 提供新捕获帧就渲染，程序不限制为 60 帧。支持的系统会将捕获的最小更新间隔设为零，显卡呈现排队上限设为一帧；捕获缓冲中已有两帧时直接处理较新的一帧，避免等待旧画面。也可选 30、60、120、144、240 帧上限。它跟随的是 Windows 捕获帧，不是游戏内部帧率；显示器刷新率、系统捕获速度、框的尺寸和显卡开销仍可能影响结果，不能保证与游戏每帧一一对应。静止画面的更新频率由系统决定；拖拽或滚轮变化时会用最近画面重新渲染，避免静止画面不响应操作。首次在 SDR 画面上验证，HDR 色彩和独占全屏兼容性还没有覆盖。

## 开发验证

`DailyToolkit.exe --benchmark-lens <JSON路径> <旧版HLSL路径>` 使用程序生成的测试纹理，对比 640 × 384 的 2×、10× 和 1600 × 1200 的 10× 渲染。GPU 时间戳记录实际完成耗时，不把图片读回、Windows 捕获或呈现等待算进着色器时间；它不能代替游戏里的端到端帧率和延迟测量。此检查不捕获桌面，不读取个人图片。

核心检查覆盖局部框尺寸、坐标、副屏边界、快捷键和模式有效性。桌面检查实际编译并执行显卡着色器，以 WARP 验证颜色保持和边缘插值；同时检查单个自定义及空快捷键、模式保存、旧设置迁移、后台窗口注册、原生消息投递、松键关闭和退出清理。

检查也覆盖高刷新率输入及限帧时序、照片实际渲染、独立宽高、拖拽边界、中心吸附与辅助线清除、固定模式的输入放行、滚轮上下限、恢复默认保留个人选择，以及预览延迟加载和窄窗口布局。

在本机可运行 `DailyToolkit.exe --check-lens <PNG路径>`。这个开发检查短暂显示程序自己的测试窗口，通过真实显示器捕获验证：浮窗显示后仍能取得下面的画面、鼠标穿透、图像更新及资源清理。完成后关闭测试窗口，只保存测试区域的 PNG 和验证结果，不保存整个屏幕。这个检查不能替代具体游戏的运行验证。

`DailyToolkit.exe --check-lens-shortcuts <JSON路径>` 在真实桌面验证后台首次开启、同键关闭、完整资源释放后的重新开启、启动中取消、按住开启、松开关闭、拖拽位置和倍率保留、固定锁住当前位置、中心吸附、恢复默认回中和清空释放。开发检查临时注册并生成 F24 按键，用实际鼠标输入从框中间拖动并调倍率，覆盖移出原窗口后的连续拖动。除窗口坐标外，也读取程序自己的测试区域，确认放大画面随浮窗移动、原位置露出下方画面，以及辅助线显示在桌面上且避开放大内容；保存该测试区域的前后 PNG 和 JSON，不截取整个屏幕。输入只作用于程序自己的测试画面，结束后恢复鼠标位置。不发送文字或修饰键，不更改用户设置。放大框、辅助线、测试窗口和临时注册会在结束后释放。请在交互桌面运行；隔离桌面不能验证真实按键和显示。

该检查还确认运行中调倍率不重建浮窗或捕获，连续调节后保留最后的参数；照片框在屏幕边缘扩大后，仍能从显示的位置继续拖动。模拟捕获失败后完整清理，以及自动使用鼠标所在屏幕和活动会话释放也在检查范围内。检测到两块或更多屏幕时，使用不同颜色的自有测试窗口，验证一直按住鼠标跨屏往返后取得对应画面、保留浮窗和拖动，并恢复大屏上的设定尺寸。单屏运行会把 `CrossMonitorDragVerified` 记录为 `null`，不计为跨屏通过。模拟失败只触发内部失败信号，不断开显示器或改动驱动。使用重构前同一着色器运行 `--benchmark-lens` 时，结果同时记录前后像素哈希，可用于核对输出一致；读回不计入显卡耗时。

捕获 API 和排除设置来自微软公开接口；底层 Direct3D 调用使用 Vortice，算法和工具逻辑由本项目实现。依赖许可证见 `THIRD_PARTY_NOTICES.txt`。
