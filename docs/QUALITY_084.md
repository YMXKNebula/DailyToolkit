# 0.8.4 质量检查与验收边界

0.8.4 继续使用现有功能和界面，重点是关闭功能后的资源释放、空闲开销、数据保护与故障定位。本文是执行入口和证据要求；列出检查不代表已经通过，也不构成 1.0.0 的发布规则。

## 可重复的自动检查

使用 .NET 10 SDK。默认分析器和 NuGet 的直接、传递依赖审计已经存在；本次补充可独立留存的报告和少量有明确目标的分析规则，不重复建立分析体系。

```powershell
# 本地安全检查：临时数据、无真实键鼠/UAC/安装。
./scripts/check-quality.ps1

# 独立依赖报告；先完成对应源码的 build/restore，命令会查询已配置的漏洞数据源。
./scripts/audit-dependencies.ps1

# 可手动运行的长期检查，使用临时存储和 FakeClipboardAccess 等隔离适配器。
./scripts/test-background-stability.ps1 -DurationMinutes 60
```

`check-quality.ps1 -IsolatedCi` 仅供可丢弃的 CI runner：保留原有核心、完整 Desktop、剪贴原生事件/媒体、配色和 FilePack 恢复检查，追加后台生命周期、诊断隐私和界面渲染检查。它不允许在普通用户桌面直接启用这组完整原生检查。本地默认模式显式记录未执行的原生项目。

质量与长期检查为每次运行在输出目录内创建独立临时夹具目录，仅修改当前 PowerShell 进程及其子进程的 `TEMP`/`TMP`，结束时恢复原值，不改用户或系统环境配置。测试自行清理其已知夹具；失败后剩余内容保留供检查，入口脚本不递归删除未知路径。

普通 CI 在打包前执行短资源回归，汇总 `summary.json` 中每项 `passed`、`failed`、`skipped` 和日志路径。构建失败导致后续检查无法运行时，后续项目为 `skipped`，整体为 `failed`。未执行的手工场景始终保留为 `skipped`，不折算为已验证。

每周定时运行 180 分钟隔离稳定性检查；手动工作流可选择 60、180、300 分钟，给 runner 的构建和清理预留时间。定时检查不打包、不安装、不发布。测试失败或超时时保留已有日志、采样和报告，不以空报告视为通过。该测试验证可控适配器和临时数据的生命周期；真实硬件、系统后台及日常长时间使用仍需独立验证。

依赖报告包括直接和传递 NuGet 组件清单、已知漏洞，以及随包 7-Zip 可执行文件和对应源码的固定 SHA-256。7-Zip 哈希只能证明内容一致；上游安全公告仍需单独核对，报告明确标记 `manual-required`。有漏洞、无效 JSON、数据源诊断或查询失败均使审计失败，不关闭审计或忽略警告。

检查结果和失败截图作为 `quality-check-diagnostics`、`background-stability-diagnostics` 工件保留 14 天，安装失败证据继续由独立安装任务保留。CI 路径/夹具日志与下述用户诊断报告是不同输出；不能把原始测试日志作为用户脱敏报告。

## 用户主动导出的诊断报告

入口：设置 → 关于 → 诊断报告。沿用现有折叠区域、按钮模板、MutedText 和当前主题资源，没有新增颜色或共享样式。默认折叠，展开后可导出或清除。

报告仅包含数字版本、功能开关、进程运行分钟数、按桶取整的内存/句柄/线程/累计 CPU 计数，以及固定枚举的模块/错误类别。错误队列最多 64 条，只驻留内存，用户清除或进程结束即清理；没有磁盘常驻日志、周期采样、自动联网或自动上传。不采集笔记/剪贴/文件内容、文件路径、用户名、机器标识、异常消息或调用栈。异常接入只分类记录，不标记为已处理，不以捕获全局异常后继续运行为恢复机制。进程终止后的历史记录不保留。

导出先写选定位置旁的临时文件，成功后替换报告；取消或失败保留已有文件，并尝试清理临时文件。权限/磁盘变化也可能导致临时文件清理失败，此时不会删除其他文件或改权限。

## 仍需有条件的人工验收

| 场景 | 应确认的结果 | 自动检查的边界 |
| --- | --- | --- |
| 真实混合 DPI、跨屏 | 文字、命中区域和放大框一致，跨屏不产生明显尺寸跳变 | 100/150/200% 位图渲染不是显示器实测 |
| 睡眠、唤醒、锁屏、全屏游戏 | 资源可重建，未使用时停止捕获，恢复后快捷键和数据可用 | 隔离适配器不替代系统状态转换 |
| GPU 设备丢失、驱动重启 | 停止无效捕获并明确反馈，可重新开启 | 不为测试主动重启驱动或破坏当前桌面 |
| 磁盘满、权限变化、异常中断 | 最新可保存数据得到保护；旧文件不误覆盖；恢复状态清楚 | 临时夹具注入只能覆盖代码路径，不等于实体盘故障 |
| 真实旧版升级到 0.8.4 | 笔记、历史、配色、快捷键和任务记录保留；取消下载、校验失败可恢复 | CI 的安装夹具不是用户真实安装或全部历史版本迁移 |
| 长时间真实后台运行 | 关闭功能后无该功能的监听/任务/捕获；空闲 CPU/句柄不持续增长 | .NET/WPF/托盘的共享进程基线不能按模块归零 |
| Windows 10、ARM64、x86 | 仅在承诺支持前取得对应环境完整证据 | x64 编译/测试不推导其他架构与系统支持 |
| 代码签名 | 使用明确授权的正式发布者身份，检查最终签名和时间戳 | 未配置证书或托管签名身份；不得伪签或宣布已签 |

上述涉及实际用户数据、自启、安装、系统输入、UAC、网络/VPN、应用关闭或电源的动作，不由检查脚本自动执行。现有网络变慢反馈尚无归因证据，不能因资源测试通过而宣布已解决。

对外发布记录应写明本轮实际通过项、跳过项和剩余限制，并核对发布包自身；历史版本和先前 CI 成功不替代 0.8.4 对应源码与产物的验证。
